# 操作与故障排查

用于中文和英文的部署、操作说明、Runbook、安全说明及多步骤 API 流程。许可与署名见 [LICENSE](../LICENSE)。本指南直接给出适用的检查方法，不强制句长或受控词表。

## 读者能否执行并验证

- 动作前交代必要环境、权限、前置状态、适用版本及警告。不得把会影响执行的条件藏在步骤后面。
- 写清谁执行什么。人工操作与系统自动行为分开；不能将「保存后系统重载」改成人工重载服务。
- 多个必须依次完成的动作使用编号步骤；不可分或必须同时完成的动作可以保留在同一步。不把条件与动作拆散到难以对应的位置。
- 核对命令、路径、参数、资源对象及执行顺序。缺少真实命令或环境值时提出补充要求，不发明可运行的示例。
- 必要时说明预期输出或可观察结果，便于读者判断步骤是否成功。失败时是否停止、可以安全重试还是需要恢复，都应有依据。
- 保留备份、风险、限制、回滚条件和禁止事项。危险操作应清楚说明对象、后果和是否可撤销；缺少信息时标记缺口。

## 排查要依据观察

1. 说明可观察到的症状、影响范围和适用环境。
2. 指出用于区分原因的日志、状态、错误码或其他现有证据。
3. 优先安排风险较低、可逆且能排除原因的检查；每项给出判断条件和后续分支。
4. 原因没有确认前保留「可能 / may」。不要把常见原因写成已确认根因。
5. 恢复后检查原症状是否消失；现有资料要求停止或升级处理时保留这些条件。

这是检查思路，不是每份文档必须采用的目录。未知的日志路径、阈值、恢复命令、联系方式和处理期限均不能自行补齐。

## 双语示例：不改变责任和条件

原文：

> 选择保存以后系统会写入配置并重新加载服务。温度超过允许范围时，不要启动设备。
>
> After you select Save, the system writes the configuration and reloads the service. Do not start the device if its temperature exceeds the permitted range.

建议：

> 选择「保存」。系统随后写入配置并重新加载服务。如果温度超过允许范围，不要启动设备。
>
> Select Save. The system then writes the configuration and reloads the service. If the temperature exceeds the permitted range, do not start the device.

保留系统行为、温度条件和禁止关系，不补充未知温度值。项目已有按钮格式规范时沿用其格式。

## 双语示例：缺少恢复依据

> 请求超时后重试，直到成功。 / If the request times out, retry until it succeeds.

先核查任务是否可能仍在后台执行、重复请求是否会产生重复副作用、重试上限和停止条件。信息不足时提出缺口，不把它擅自改成固定次数、固定间隔或先取消后台任务。
