# API 与错误信息

仅在审阅中文或英文 API 说明、接口状态和错误信息时读取。许可与署名见 [LICENSE](../LICENSE)。示例用于说明区别，不替代待审接口的实际规格。

## 对照接口契约

- 核对方法、路径、字段、枚举、类型、单位、是否必填、允许值、默认值和省略参数后的行为。空值、空字符串与未提供参数不一定相同。
- 检查参数依赖、互斥条件、版本和权限要求。默认值不等于建议值；示例值不等于默认值。
- 请求、响应、示例和正文应一致。代码及机器可读内容默认保留；若接口契约确实有错，单列纠正建议，批准后再改。
- 说明调用成功意味着什么、任务何时结束、结果从哪里取得；仅在规格支持时补充轮询、回调、重试、幂等性或分页说明。

## 状态不能只按单词翻译

区分 HTTP 响应、业务结果、后台任务状态和界面标签。状态词的具体含义由接口定义决定。

| 容易混淆的情况 | 审阅判断 |
|---|---|
| Accepted / 已受理 | 不自动表示处理完成或业务成功；异步接口应说明后续如何确认结果 |
| Pending / 待处理 | 不直接改成 Running / 处理中；确认任务是在等待、执行还是等待人工确认 |
| Unauthorized 与 Forbidden | 核查认证和权限的区别，不把身份验证失败统称为无权限 |
| Invalid / 无效 | 说明无效的对象或格式；不在没有法律含义时机械写成「非法」 |
| Unsupported / 不支持 | 不凭空添加「暂」或承诺以后支持 |
| Failed、Timeout、Expired | 区分任务失败、请求等待超时和资源过期；超时不一定表示后台任务失败或已取消 |

保留接口实际返回的状态码和原始消息。必要时在其外增加解释，不直接覆盖引文或返回字面量。

## 错误信息要让读者知道怎么办

检查信息是否说明：发生了什么、影响哪个对象、已有依据的原因、可执行的恢复动作，以及仍失败时应收集的诊断信息。按实际需要提供，不强制每条提示包含五部分。

- 区分可能原因和确定原因，不承诺未知恢复时间。
- 不把「没有数据」「尚未创建」「没有访问权限」「加载失败」合并成相同的空状态。
- 不因为文字简短而删掉限制、兼容性说明、安全警告或必要的恢复条件。

若接口定义已确认请求只入队，可将：

> 请求成功，任务已完成。 / The request succeeded and the task is complete.

建议改成：

> 请求已受理，任务等待处理。 / The request was accepted. The task is waiting to be processed.

这属于依据接口事实纠正状态，而非纯措辞调整。没有队列状态的证据时，不能自行加入「等待处理」。
